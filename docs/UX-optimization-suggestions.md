# 用户视角功能优化建议

从「用户怎么用」出发整理的优化点，按优先级和模块分类。

---

## 一、首访与发现

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **未登录时的价值说明** | 首页有「Sign in to create」和 Demo 对话，但「为什么要登录」「登录后能做什么」不够直观 | 在首页或 signin 页加 1–2 句：登录后可保存游戏、多设备继续、分享链接等 |
| **Discover 未登录点击创建** | 点模板会 toast「Please sign in」并跳转 signin | 可在跳转时带 `returnUrl=/create?preset=xxx`，登录后直接进该预设，减少重复选择 |
| **语言混用** | 界面中英混用（如「Game Document」+「隐藏规则预览」） | 统一为中文或英文，或做简单 i18n，避免同一屏两种语言 |

---

## 二、创建游戏（Game Master）

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **规则文档为空就点 Start Game** | 会 toast「Please add some document content first」 | 可考虑在规则为空时弱化或禁用 Start Game，或按钮旁加小提示「先和 GM 聊几句生成规则」 |
| **会话列表无标题** | 新会话可能显示为「New Game Setup」等通用名 | 已有根据首条消息生成标题的逻辑，可再检查是否在所有创建路径下都会更新 |
| **API Key 未配置** | 会 toast 报错 | 首次报错时可考虑引导到「配置说明」或文档链接，而不是只报错 |
| **语音输入不支持** | 不支持的浏览器会 toast 提示 | 可在麦克风按钮旁用图标/小字标注「仅部分浏览器支持」，减少误点 |

---

## 三、游戏房间内

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **Settings 入口** | 频道列表底部点齿轮会 toast「Settings coming soon」 | 短期：改为「游戏内设置」说明（如音效、通知），或隐藏/禁用并加 tooltip「即将推出」；长期：落地真实设置页 |
| **分享链接** | 复制后 toast「Link copied」 | 可补充一句「把链接发给好友即可一起玩」，或复制后短暂显示完整链接便于核对 |
| **Game not found** | 游戏不存在或已删除时显示「Game not found」+ Go Home | 可增加「去我的游戏」按钮，或列出最近游戏方便找回 |
| **规则/进度只读** | Sections 为只读展示，无法在房间内编辑 | 若产品上不打算在房间内改规则，可在 UI 上弱化「可编辑」感（如去掉像输入框的样式） |

---

## 四、我的游戏 & 侧栏

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **My Games 统计** | 次数、人数、评分等为 mock 随机数 | 若暂无真实数据，可先隐藏或改为「—」，避免误导；有数据后再展示 |
| **侧栏「Upgrade to Pro」** | 点击无实际行为 | 可链到定价页/邮件订阅，或暂时隐藏/改为「反馈」等有用入口 |
| **侧栏「Help & Support」** | 点击无实际行为 | 可链到文档/FAQ/Discord，或临时改为「反馈与帮助」邮件/链接 |
| **删除游戏** | 侧栏右键 Delete，有二次确认 | 已较完整；若游戏较多，可考虑在 My Games 页也提供批量操作入口（如多选删除） |

---

## 五、账号与个人

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **登录方式** | 仅 Google | 若目标用户有不用 Google 的，可后续加邮箱/其他 OAuth；当前可在 signin 页注明「使用 Google 登录」 |
| **头像/昵称** | 依赖 Google 与 callback 写入 user_metadata | 已做 refresh 与多处展示优化；可再确认在无头像时 fallback 统一（首字母+背景色） |
| **Profile 编辑** | 有 User Profile 页 | 侧栏「Edit Profile」会跳转；可检查「保存成功」是否有 toast 或页面内反馈 |
| **登出** | 侧栏用户菜单中有 Log Out | 流程清晰；可考虑在敏感操作（如删除账号）前再次确认 |

---

## 六、空状态与错误

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **My Games 空状态** | 已有「No Games Yet」+ 创建引导 | 保持即可 |
| **Game Master 无会话** | 有 New Session | 可考虑首次进入时自动建一个空会话并聚焦输入框，减少一次点击 |
| **网络/接口失败** | 多处 toast.error | 对「创建游戏」「发送消息」等关键操作，可加「重试」按钮或自动重试一次 |
| **游戏加载中** | gamesLoading 时显示 loading | 若列表来自远端，可区分「列表加载中」和「当前游戏加载中」的提示 |

---

## 七、无障碍与体验细节

| 优化点 | 现状 | 建议 |
|--------|------|------|
| **键盘与焦点** | 部分表单可键盘操作 | 确保「发送消息」「Start Game」等主按钮可 Tab 到并 Enter 触发；模态框关闭后焦点回到触发按钮 |
| **分割条** | 已加 role="separator" 和 aria-label | 可再确认拖拽时是否有键盘可用的替代（如左右箭头微调宽度） |
| **加载状态** | 多处 Loader2/spinner | 对耗时操作（如 Start Game、生成 Host）保持或加强「进行中」说明（如「正在生成主持人…」） |
| **移动端** | 布局有响应式 | 侧栏在窄屏下可考虑折叠为抽屉，避免聊天/游戏区域过窄 |

---

## 八、可后续迭代的功能

- **游戏内设置**：音效、通知、主题等（当前为 coming soon）
- **帮助中心**：规则说明、常见问题、快捷键说明
- **Pro/付费**：若不做付费，可隐藏或改为「赞助/反馈」；若做，需有清晰权益说明与入口
- **多语言**：统一文案语言或接入 i18n
- **数据持久化**：游戏列表、会话、房间状态若与后端同步，可考虑「上次玩到哪」的续玩引导

---

## 建议实施顺序（按性价比）

1. **高优先级**：Discover 预设 + returnUrl；Game not found 增加「我的游戏」；Start Game 在规则为空时的提示或禁用。
2. **中优先级**：Settings/Help 改为真实链接或暂时隐藏；My Games 统计改为真实或隐藏；首访/登录价值说明。
3. **体验打磨**：语言统一、键盘焦点、关键操作重试、移动端侧栏。

如需我针对某一类（例如「只做游戏房间内」或「只做首访与发现」）拆成具体改法或直接改代码，可以指定模块。
